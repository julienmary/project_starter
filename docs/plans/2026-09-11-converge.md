# Plan — Adapt spec-kit's converge idea to project_starter

Date: 2026-09-11. Design discussed and validated in session.

## Idea

The drift question (commit-time) asks: "does the vault still tell the truth about
the code?". The converge pass asks the reverse: "does the code do everything the
vault promises?". Adapted from spec-kit's `/speckit.converge`, stripped of its CLI
and per-feature machinery: one method file, append-only writes, human cadence.

## Validated decisions

1. **Gaps location**: `missing`/`partial` gaps go in a dated `## Gaps (convergence
   YYYY-MM-DD)` section at the bottom of the node concerned (one file = one
   responsibility; selective loading keeps working). `contradicted` and `uncovered`
   findings go to `OPEN.md` (there is a decision to make / the vault lies by
   omission).
2. **Trigger**: manual (paste `CONVERGE.md`, cold-review cadence) + a soft,
   non-blocking reminder in the Claude Code hook when the `Last convergence` date
   in `INDEX.md` is older than `VAULT_CONVERGE_EVERY` commits (default 30,
   `VAULT_CONVERGE=0` disables). Reminder paced by `.git/vault-converge-reminded`.
3. **Form**: `CONVERGE.md` alone, symmetric to `COMPILE.md`, agent-agnostic. No
   slash command, no CLI.

## Changes

- `CONVERGE.md` (new): the convergence prompt with contract — intent inventory
  from `decided`/`stable` nodes + `DECISIONS.md`; inspection bounded to what the
  vault asserts; gap types `missing | partial | contradicted | uncovered`;
  append-only writes; `Converged` = only the date moves.
- `INDEX.md`: add `- Last convergence: TODO date` to the State section.
- `vault-check.sh`: add `CONVERGE.md` to the pages list; check Gaps section
  format (dated header, `- [ ] missing|partial — ...` entries).
- `hooks/claude-pre-commit.sh`: add `CONVERGE.md` to `is_method_file` and to the
  adoption `cp` list; add the non-blocking converge reminder (systemMessage JSON,
  exit 0) on commits that carry project code; document it in the header.
- `README.md`: converge pass in section 5, `CONVERGE.md` in the tree and in the
  method-files list.
- `AGENTS.md`: committing rule — a gap fixed by a change is checked `[x]` in the
  node's Gaps section, committed with the code under `Vault: updated`.

## Non-goals

- No blocking behavior for convergence (the user's own argument: a hook that nags
  gets uninstalled).
- No task IDs, no phases, no per-feature directories — the vault's node is the
  unit, not the feature.
